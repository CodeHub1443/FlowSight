### Deviations and decisions

1. **`shiftOf` and `shiftBounds` take a `businessDayStart` argument** (`shiftOf(ts, shifts, businessDayStart)`, `shiftBounds(date, shiftId, shifts, businessDayStart)`). The brief's signatures omit it, but the business day of the overnight shift C cannot be derived from the shifts alone. Both return `null` (not throw) for a gap or unknown id.
2. **`formatPlate(plate)` has no `lang` parameter.** Bangla is primary and English secondary regardless of UI language (CLAUDE.md, docs/01 section 7), so a language argument would be unused. Returns `{ primary, secondary }`.
3. **`formatDuration(sec, lang, digits?)`** has an optional third argument for the Latin/Bangla digit toggle; default follows the language. Minutes are truncated, not rounded.
4. **`WhEventSchema` / `WhEventWithStatusSchema` are zod transforms** around `parseWhEvent`, so events validate inside `Page<T>`, snapshot and replay shapes with the registry's typed union as output. `WhEvent` is a discriminated union on `category` + `type` (narrowing gives a typed `data`).
5. **Bay ids are validated by format `B\d{2}`**, not the range B01-B07 (site config is data, other sites may have more bays).
6. **Free-text `note` fields in SiteConfig are optional**, all other config keys are required. Open vocabularies in the config (`roof.type`, `bayOrder`, `gate.position`, `facade.pattern`, ...) are plain strings because only one value is known.
7. **`contract:check` loads the TypeScript schemas through Vite SSR** (`createServer` + `ssrLoadModule`) so no new dependency (tsx) is needed. It takes `--doc <path>` for tests. It takes about 5 s.

## Task 12: scene dropped to the Low tier on a real GPU (uncommitted)

### Root cause (reproduced headed, real Chrome, RTX 3050, 165 Hz panel)
drei `PerformanceMonitor` counts every step in `flipped`, inclines included, and `flipflops={4}` fired `onFallback` -> `setAutoTier('low')` after the fifth. High was already the top tier, so a fast GPU kept "inclining" every 2.5 s and locked itself to Low. No decline ever fired. Hypothesis 1 (low fps, DevTools, occlusion) was wrong; the same log came with and without DevTools.
`incline` flipped 1..5 at 105-150 fps, then `FALLBACK` at 113 fps (1920x1080) and 129 fps (1910x902, DevTools). Low then ran at 124-141 fps. The logs also show why warm-up is needed: the first sample after load or a tier step reads 1-3 fps.

### Fix
- `src/scene/tierGovernor.ts`: pure state machine, replaces PerformanceMonitor. 5 s warm-up, then waits for the models (at most 30 s) and settles 3 s; pauses while hidden or unfocused; 1 s fps windows. Down: High below 40 fps for 6 s, Med below 20 fps for 8 s (80 % of the windows). Up: Low at 40+, Med at 55+ for 10 s. A tier left within 30 s of stepping up to it waits 60 s before a retry, doubling to 30 min.
- `src/scene/AutoQuality.tsx`: drives it from `useFrame`; React state only on a step. `SceneRoot.onTierChange` reports the tier, so the Low card-blur fallback now follows automatic steps too (closes the BACKLOG item "SceneRoot does not report automatic tier steps").
- Software-renderer regex is now `swiftshader|llvmpipe|softpipe|microsoft basic render driver`.
- Dev: `?quality=auto` joins `high|med|low`; `QualityBadge` (bottom centre) and `window.__qualityProbe` exist only in `pnpm dev` and `VITE_DEBUG_PANEL=1` builds (0 mentions in a production `dist`).

## Task 13e: two e2e failures, root causes, Task 13 committed

### Root causes
1. **The slow, moving e2e failures, including `auto-quality` "a fast GPU climbs to High" and the Task 13d runs: Windows throttles the test browser while another browser is in front. Not an app defect.** Measured on this machine (i7-13620H, 6P + 4E) with one sample per 15 s through a full run: foreground IDE or terminal, all 16 logical CPUs busy and Chrome at 11-14 cores; foreground Firefox or Chrome, only CPUs 12-15 (the E-cores) busy and Chrome at 3.8 cores, switching within one sample of the focus change. SwiftShader needs those cores, so pages miss every timeout while the machine looks idle. Every failure of that run fell in the E-core window. Opting only the `chrome-headless-shell` processes out of power throttling (`SetProcessInformation`, `ProcessPowerThrottling`, execution speed) gave all 16 cores with Firefox still in front, and the 5 failed tests passed at normal durations.
   - `med · pinned · - fps` under `?quality=auto` is that starvation, not parsing: `SceneRoot`, `AutoQuality`, `LiveScene` and `quality.ts` have no Task 13 diff. `pinned` is the probe's initial value, shown until `AutoQuality` runs its first frame, and `med` is `LiveScene`'s initial tier. Both stay on screen while the scene chunk is still loading.
   - One earlier run was also hit by a real sleep (10:46, Start menu, then AC unplugged and hibernate until 11:46). The first stalls of that run came before the sleep, so sleep is not the general cause.
2. **`live-flicker`: the spec sampled before the language switch had landed. Not an app defect.** After clicking বাং it awaited `fonts.ready` and a fixed 1 s. At 60x on SwiftShader (under 2 fps) the switch landed 0.9-3.3 s after the click (6 of 6 probes), with the tweening `Num` last to repaint, so the sampler could record the Latin-to-Bangla change as a size change (`kpi-label-cases` 132.3 -> 133.5: two digits at 7.78 vs 7.17 px). Within one language the delta and label boxes did not move across any digit change. Task 13's unique KPI testids let the spec measure labels properly for the first time, and that exposed the wrong wait. The test id `tray-bay-B02` not found in the original report is root cause 1.
