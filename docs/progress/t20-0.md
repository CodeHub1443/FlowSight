## Decisions (with reasons)
1. **Merged cohort = `band: null`** (spec section 3 types `band: 1 | 2 | 3`). The spec's merge rule ("a cohort with fewer than 6 visits merges
   its bands") produces a cohort that is no single band, so the type gains `null` and the key ends in `.all`. Everything else in the spec's types
   is as written. This is the one deviation from the spec text; flagged for the backend in the contract diff.
2. **Merge granularity.** If any non-empty band of a `dir x pack` group has fewer than 6 units, the whole group becomes one cohort (bands are
   cut at terciles, so a small band means a small group). Only cohorts that are used are listed in `cohorts[]`, ordered by key.
3. **"Dominates" = more than half** of the counted cartons (strict majority), `UNKNOWN` SKUs counted with the pack the belt camera gave them;
   no majority or an empty `sku[]` gives `MIXED`. The spec did not define "dominates".
4. **Terciles with linear interpolation** (Postgres `percentile_cont`), band 1 `<= q1`, band 2 `<= q2`, band 3 above; medians the same way.
   Chosen so wh-api can compute the identical numbers in SQL.
5. **Index unit also needs `activeMin > 0`**, and "finished in range" = `finishedAt` in `[from, to)`. Every count, mean and median of the
   response uses that same set of visits.
6. **Crew.** `avgCrew` = loading-time-weighted mean of the people the CREW camera sees in the bay (simulator: `crewTotal` = workers + captain
   + forklift operator, the same field `/analytics/productivity` uses). With that weighting `cartonsPerCrewHour` is exactly cartons per
   crew-hour. A visit without a crew count (0 in the simulator) is left out of both crew numbers.
7. **Rounding:** computed unrounded; index, means, medians, rates, `avgCrew` to 1 decimal; `medianMinPer100` to 2.
8. **"DataSource client method" = `getBayPerformance()` in `src/data/api/endpoints.ts`.** docs/02 puts REST in `data/api` (react-query
   hooks in `queries.ts`); the `DataSource` interface carries only live channels, so the method is not added there. No conflict with docs/02.
9. **QueryClient.** The app had none. Added in `AppShell` (the root layout route) rather than `App.tsx`, so route-level tests that render
   `AppRoutes` get it too. React Query is now in the entry chunk (see bundle).
10. **Periods.** `shift` = the running shift instance, `day` = the business day from `businessDayStart`, `week` = the last 7 business days
    including today; nominal bounds `[start, end)`, data to `min(end, now)`. Previous period = same nominal length immediately before,
    complete (for `day`: yesterday 06:00 to 06:00), so W4 can draw "a normal day" against today; align points with `offsetInPeriod`.
    A shift range inside a gap between configured shifts falls back to the day. Shifts come from `config.shiftsPlaceholder`.
11. **"Now" for the range** = the newest stream timestamp (`liveStore.lastTs`), else the wall clock, read when the query runs. In mock
    speed-up and replay the wall clock is wrong for the simulator's visits. The window is resolved inside the query function, so the query key
    stays `[analytics, endpoint, site, range]` and a 60 s refetch rolls over at a shift or day boundary by itself.
12. **Range default not written to the URL** (`/analytics` = day); other values set `?range=`, kept when switching tabs.
13. **Simulated-data marker**: a neutral pill "Simulated data" (`analytics:simulated`) in the page header in mock mode, with a tooltip.
14. **Band tones**: slower `warn`, comparable `neutral`, faster `info` (not `ok`: no red/green shouting). In `perf/constants.ts`.
15. **Other tabs** reuse the existing `Placeholder` (title from `analytics:tabs.*`); unknown tab -> `NotFound`.
16. **ECharts preload.** The Performance tab calls `preloadChart()` on mount, so the ECharts chunk downloads while the widgets fetch data. It
    also makes the bundle check meaningful now (with no widget yet, nothing else imports `<Chart>`). Page tests stub `chart/load`.
17. **Chart wrapper** is our own (~100 lines over `echarts/core`), not `echarts-for-react`: it needs the theme re-init on light/dark, the
    locale formatter fill-in, the font redraw and reduced motion, which the library does not do. `echarts-for-react` stays an unused
    dependency (no package change in this task).

## 20.0b: calibrate the bay index (spec corrections)
Problem: median-based expected minutes sit below the mean actual minutes on right-skewed durations, so on mock data six of seven week
indices were under 100 and "100 = comparable trucks" misled. Contract rev 1.2 is unreleased, so definition 8 was edited in place.

**Definition 8 now:** `index = 100 x (sum expected_b / sum actual_b) / (sum expected_all / sum actual_all)`; `_all` = every included unit of the
site in the range (also those of bays with confidence NONE). Null when a bay or depot denominator is 0 or nothing is included.
100 = typical for this depot's comparable trucks. Median cohorts, merge rule, confidence thresholds and the response shape are unchanged.
