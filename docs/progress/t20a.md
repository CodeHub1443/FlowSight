## Decisions
1. **W1 is HTML, not a chart.** Every value is text, so no hidden data table is needed; the bar is `aria-hidden`, the band is announced in text.
2. **Scale** is centred on 100 and spans at least twice the 90-110 band on each side, widening to the largest shown deviation. LOW rows are drawn muted (50 % opacity bar, muted number). NONE rows show no number and no bar.
3. **Tones** from `INDEX_BAND_TONE` (slower warn, comparable neutral, faster info). Comparable numbers use ink, not a status colour.
4. **Bay order** is enforced in `inBayOrder` (numeric id collation) in all three widgets, regardless of the order the API sends. Nothing sorts by value.
5. **W2** uses the same `SEGMENT_TONE` as the KPI popover and bay timeline. Unknown phases draw as 0 and read "-" in the tooltip and data table. The label is "Loading" if `cartonsOut > cartonsIn`, "Unloading" if the reverse, "Loading / unloading" on a tie or zero. A zero-width transparent cap series carries the occupancy label at the bar end. The axis maximum is a "nice" number covering the bars and the median.
6. **W3 crew columns are hidden** when no bay has a crew count (cannot be measured), per the metric admission rule; unknown cells in a measured column show a dash with a reason (no trucks at this bay / not measured). Header: "Cartons per hour, per crew member present".
7. **Insufficient states:** W1 per spec (n = highest `included`); W2 when no bay has any phase or occupancy value; W3 when no bay has a loading rate. All three go empty first when `site.visits` is 0.
8. **Strings:** the shared `analytics` keys (`state.*`, `confidence.*`, `band.*`, `visits`, `siteMedian`) are reused; the rest are in `perfindex`.
9. **Type-only imports** of `echarts` types in `timeSplitOption.ts`; the Chart wrapper stays the only runtime ECharts entry. Imports `useFmt` type from `@/features/live/useFmt` because `Fmt` is not re-exported by `@/features/live` (no shared file edited).
