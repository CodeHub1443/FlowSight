## Decisions
1. **Filter state lives in `kpiDetail/trayFilter.ts`, not in `Tray.tsx`.** The spec says "inside the tray files (Tray.tsx)", but Tray.tsx may only export
   components (`react-refresh/only-export-components` is an error), and the writer (alerts popover) and the reader (Tray) are different modules.
   `kpiDetail/**` is in the 19A column; nothing is in `src/stores/**`. The tray switches tab with the existing `uiStore.setTrayTab('alerts')`.
2. **`AlertFilter.categories` is not used for the group filter.** Groups split categories by type (Idle & stoppage = `belt.empty_run` +
   `security.door_open_idle`; Security = the rest of `security.*`), which a category list cannot express. The tray keeps its role-filtered
   `useOpenAlerts()` list (the `AlertFilter` path: role, OPEN/ACK) and narrows it with the 19.0 predicate `matchesAlertGroup`.
3. **Filter lifetime:** set by a group row; cleared by the clear button or by leaving the Alerts tab. The tab count stays the total of open
   alerts; the bar shows the group count. A collapsed tray re-opens: the panel is keyed by an "open request" counter (CollapsiblePanel is
   uncontrolled and shared); the key is constant between requests, so live updates never remount it (flicker test passes).
4. **Alerts chip sub-line is compact: a dot and count per severity** (critical / warn / info, critical in `text-critical-ink`), with the full
   sentence "4 critical, 70 warning, 9 info" as accessible name (`role="img"`) and tooltip. Reason: at 1366 px the chip text column is about
   127 px; the old "4 critical · 70 warn" just fits, the three-word sentence does not and would be cut (live-visual e2e forbids ellipsis).
   The popover shows the full sentence.
5. **Turnaround chip delta:** `avgTatDeltaMin` is the depot turnaround's delta, so it sits on the chip only in the legacy view; in the full
   view it moves to the "Depot turnaround" row of the popover. Before the first SiteState (`kind: 'none'`) the label is "Avg turnaround".
6. **Popover trigger is a transparent button over the chip**, so the chip stays a `<section>` and never nests interactive content. The text sits
   above it with `pointer-events: none`, except MaybeValue's "—" tooltip triggers (matched by their `.cursor-help` class), which stay
   hoverable. `data-testid`: trigger `kpi-open-<id>`, panel `kpidetail-<id>` (ids: cartons, turnaround, ppe, alerts).
7. **Popover values are plain text** (no tween) and carry `data-value` = the raw store value, so tests compare text with value.
8. **Rate now:** "—" with "No belt is running right now" when no belt runs (selector returns null); "No data yet" before any BayState. With belts
   running in one direction only, the other shows a measured "0/h".
9. **PPE popover:** score, most violations today, and the definition (PPE-only; safety events counted under Safety). No per-bay list (not in the
   admission table).
10. **Stacked bar colours:** pre-op `warn`, loading/unloading `info`, post-op `neutral` (tokens). The bar is hidden when the shares are unknown.
11. **Chip visibility is unchanged:** turnaround from 1700 px, PPE from 2000 px (the row must not grow). So at 1366 px only the cartons and alerts
    popovers are reachable, and at 1920 px the PPE chip is hidden. The e2e spec uses 2560x1440.
12. **"Other" group:** catalogue types the table does not name (e.g. `truck.unknown_plate`) land in Other; tested. A category outside the
    catalogue cannot reach the UI (zod rejects it); note that `rbac.canViewCategory` would throw on one (shared file, not changed).

## Risks / for 19.9
- **"Never covers a bay at 1366x768" is unverified.** The popover is 320 px wide, anchored under the chip, height up to the available space.
  In the default framing the bays run diagonally under the chip row (B07 near x 130-260, y 390; B01 near x 640, y 200), so the cartons popover
  (x 68-388) and the alerts popover (x 712-1032) may overlap bay doors while open. Check the screenshots; possible fixes are a shorter popover
  or `align="end"`.
- Alert groups come from the role-filtered alertStore; the "Needs attention" total comes from `kpi.openAlerts`. They can differ (role filter,
  store retention), so group sums are not asserted equal to the headline.
- 19B draws a per-visit stacked bar; colours here are pre-op warn / work info / post-op neutral. Align if 19B differs.
- The PPE chip sub-line "Most violations today: Bay 3 (7)" may truncate in a 236 px chip at 2000-2100 px (it has a tooltip); live-visual
  only checks 1920 and 1366, where the chip is hidden.
- The existing e2e specs select `[data-testid^="kpi-"]`; the new always-mounted `kpi-open-*` and `kpi-sev-*` elements match it (they do not
  change size or unmount on updates; the unit flicker test passes).
