## Behaviour summary (spec section 3)
- **Toast rule.** Only events that arrived on the live subject (`unreadIds`; the REST merge never sets it), sev warn or critical, role-visible, OPEN, and not within 3 s of the source going live (the connect backfill). One toast per `(category, type, bay)` per 60 s. Hygiene and belt events of one visit collapse into one toast for 5 minutes (same toast id, count and text update: "3 product issues, Bay 4"; severity escalates to the worst; the target becomes the newest event). At most 3 toasts: a fourth evicts the oldest warn toast; a warn event is skipped when all three are critical; a critical one evicts the oldest critical. Warn 8 s, critical until dismissed. Actions: "Show on map" (select the event, fly to its bay, go to `/live`) and "Open" (`/events/:id`).
- **Page.** Default OPEN+ACK, newest first; with CLOSED and no range the request carries today's business-day start as `from` (applied, not written to the URL). Filter bar: Needs-attention group chips with counts (`selectAlertGroups` over the same role-filtered open set as the KPI popover, rows filtered with `matchesAlertGroup`), status (never empty), severity, category (role-visible), bay (B01..B07), range (any, shift, today, week, custom dates), text (300 ms debounce), group-by-truck. All of it in the URL through `parseEventFilters` / `serializeEventFilters`.
- **Table.** `role=grid`, fixed 48 px rows, windowing by `windowRange` (spacers above and below, 6 rows overscan, ResizeObserver viewport), cursor paging when the end is within 10 rows, keyboard (Up, Down, Home, End, PageUp, PageDown, Enter, A, Esc), live open events merged by id (the more advanced copy wins; a row whose status moves stays in place). New live rows apply at once at the top; while the user is scrolled they wait behind an "N new" pill and nothing in view moves.
- **Drawer.** Right sheet (full width under 1024 px): severity and status, title, time, bay, camera, model confidence; snapshot with bbox + full-size dialog; clip in `<video controls preload="none">` with the snapshot as poster; references with "Show truck / bay on map"; type-specific details from `data` (`eventDetails.ts`, employee ids never shown); history (raised, acknowledged, closed with note, notes); Acknowledge, Close (note of at least 3 characters), Add note. Optimistic through `useEventAction`; on error the change is undone, a toast says why (403 gets its own text) and a refused close/note draft comes back into the box. Drafts live in the component, which is keyed by event id, so an incoming lifecycle message never clears them. Read-only roles get one line and no buttons.
- **Deep link.** `/events/:id` fetches by id; an unknown id, a failed fetch or a category the role cannot view gives the one neutral "Event not found or not available" state.
- **States.** Loading skeleton, error with retry, "No events match" with Clear filters, and the distinct "No open alerts" for the unfiltered default. Simulated-data marker in mock mode (same pill and strings as analytics).

## Gaps and decisions to review (nothing in a shared file was edited)
1. **Gap in `src/i18n/index.ts` (shared).** Spec section 2 says `events` and `reports` are lazy namespaces; the file registers both JSON files statically, so every string of this page costs entry bytes (+5.65 kB for `events.json` en+bn). The shell/live budget is met without them, but the entry total is +11.51. Making the registration lazy in 22.9 (add the bundle when the route chunk loads) removes the 5.65 kB with no change to `events.json`. 22C will add the same kind of growth through `reports.json`.
2. **Nine groups, not eight.** `ALERT_GROUPS` has nine ids (the ninth is `other`). The bar shows all of them; `other` is hidden while its count is 0 and it is not the active filter, so normally eight chips are visible. Counts come from the same selector as the popover, so they are equal by construction (tested per group).
3. **KPI popover rows now navigate** to `/events?group=<id>` instead of opening the tray filtered to the group (spec section 3). `trayFilter.ts` and the tray's group filter still exist and are tested but nothing in the popover uses them any more; remove in 22.9 if the owner agrees.
4. **Collapsed toast target.** "Show on map" and "Open" use the newest event of the collapsed toast; there is no list-of-the-visit page.
5. **Show on map from the drawer** selects `{kind:'truck', id: visitId}` and `{kind:'bay', id}`; plate and SKU rows are text only (they have no scene object).
6. **Range control.** Presets (shift, today, week) are computed from `periodWindow` with the site calendar at click time and written as `from`/`to`; "custom" is two date inputs (day start Dhaka). The preset highlight is derived from the URL, so a shared link keeps it.
7. **Pack / enum details** (`pack`, `missing`) show the catalogue code (`SACK`, `helmet`) because no translated label exists in `live.json`; `dir`, `phase`, belt `from`/`to` and `role` are translated through existing keys.
8. The drawer's sheet close button is replaced by an own close button, because the shared `sheet.tsx` has an English-only screen-reader label.
9. The first run of a toast needs the runtime chunk (about 4 kB gzip 1.8); in a LAN that is one request on the first live alert of the session.
