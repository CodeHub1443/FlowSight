# Task 20.10: W4 partial period and unknown data, minor chart polish

Branch `t20-10-w4`, baseline `021fa94` (task-20.9). Binding: the 20.10 brief (D1 to D3). No browser, Playwright, screenshots or dev server.

## What was done
| Decision | Change |
|---|---|
| D1 partial period | `buildTrend` returns `partialIndex` / `partialUntil` (the slot in progress: the current hour for shift and day, the current day for the week; null on an exact boundary and for a finished period). New pure `trendOption.ts` draws the finished slots as the solid series, and the slot in progress as a third, dashed series that starts at the last full bucket (marker hidden) and ends on a hollow marker (card colour inside, line colour ring). It is kept out of the legend. The tooltip is built by hand: "N cartons so far (until HH:mm)" for the partial slot only. Nothing is extrapolated; the previous period stays full buckets; the caption's pro-rating is unchanged. |
| D2 unknown is not zero | Mock `throughput()` returns `v: null` for buckets before `depot.historyStartMs`. `buildTrend` turns a previous-period slot into `null` when it has points and all of them are null (week: any hour of the day). `previousKnown` = no unknown hour before the same point in time. `previousToDate` and `deltaPct` are `null` unless known and above 0. W4 draws a gap for a null point (`connectNulls: false`); the tooltip shows "—". Caption: the previous total is hidden when unknown, the difference is shown only when known and above 0, otherwise "No previous-period data yet" (`trend-no-previous`, new string, EN and BN). docs/03 rev 1.2 changelog: one sentence. |
| D3 polish | Legend entry of the previous period carries the dash (`lineStyle.type: 'dashed'`, default icon for a line). W2: `headroomMax` (new, in `timeSplitOption.ts`, built on the unchanged `axisMaxWith`) rounds the maximum up to a 1/2/5 x 10^k step with at most 10 % headroom (`AXIS_HEADROOM`) instead of `niceCeil`; the "min" axis name is `nameLocation: 'end'` with `verticalAlign: 'middle'`, `align: 'left'`. |

## Notes and deviations
- The existing week test in `PerfTrendSection.test.tsx` asserted the day in progress as a full point in the solid series; it now asserts the D1 behaviour (a null in the solid series, a hollow `{ value: 1, symbol: 'circle' }` point in the dashed one). That is the intended behaviour change, not a loosened check.
- `niceCeil` in `index/rows.ts` is no longer used by W2 (not an owned file, left in place).
- Only W4 reads `/analytics/throughput`; no other consumer sees the new nulls.
- In the mock, the last 7 days are known, so the week range's previous period (7 days before) is entirely unknown: W4 draws no dashed previous line there and the caption says "No previous-period data yet". Day and shift ranges early in the history show the same. This is the intended D2 outcome.
- A bucket with no point at all counts as 0 (as before); only buckets whose points are all null are unknown.
- The legend dash relies on ECharts 5.6 drawing a line-series legend entry with the series' line style; the per-item `lineStyle` is set explicitly. Verify visually.
