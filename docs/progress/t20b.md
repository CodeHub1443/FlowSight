## Decisions
1. **W4 = sum of all bays and both directions** of `/analytics/throughput` (hourly buckets), computed client-side from two `useThroughput` calls
   (this period, `previous=true`). The bay filter re-cuts both responses in the browser (series key `B01.OUT` -> `B01`); no extra request.
2. **Granularity**: shift and day are hourly; week is per-day totals (24 h from the window start, which is the business-day start 06:00 Dhaka).
3. **Alignment**: slot `i` of the previous period = slot `i` of this one (same offset into the period). The x axis is the current period's.
4. **Stops at "now"**: a slot is `null` (not 0) when it has not started (`slot start >= window.to - window.start`). A started slot with no cartons is a
   real 0. The hour or day in progress is drawn with what it has so far.
5. **Caption**: "this period so far" and "previous period by the same time" plus the difference in percent. The previous total is built from the previous
   period's **hourly** buckets up to the same offset, the hour in progress pro-rated by the fraction elapsed, also for the week (so it is not
   rounded to whole days). Difference = (current - previous) / previous x 100, **hidden when the previous total at that point is 0**.
   It is neutral text, no red/green and no threshold.
6. **States (W4)**: loading until both responses exist; error (retry refetches both) only when there is nothing to show (data on screen stays on a
   failed refetch, `widgetStatus`); `empty` = no cartons in either period; `insufficient` = the period has not started (own text
   `perftrend:throughput.insufficient`).
7. **Bay filter is a native `<select>`** (accessible name "Bay", options in config bay order, "All bays" first). The shadcn Select (Radix) needs
   pointer-capture shims in jsdom and gives nothing here. Restyle in 20.9 if the look differs from the other controls.
8. **W5** takes `rows[].detentions` and `rows[].visits` of `useBayPerformance(range)`, in the order the rows come (bay order), never sorted. A cell
   shows the count, "of N trucks" and the percent; a bay with `visits = 0` shows "—" with the reason "No finished trucks" (visible and as
   tooltip/label), never 0. Cells with detentions use the existing `warn` tint, others the neutral tile. `empty` when the site has no finished truck.
9. **Series names** depend on the range (Today / Yesterday, This shift / Previous shift, Last 7 days / The 7 days before); bay labels come from the
   site config in the active language; numbers from `useFmt()`; day labels from `Intl` with the `beng` numbering system in Bangla.
10. **No `useMemo` for the chart option**: the React Compiler lint (`preserve-manual-memoization`) rejects it; the compiler memoizes it.
11. The e2e spec does **not** restart the simulator: the week query is not refetched, so a restart would leave the widgets on the old data.
